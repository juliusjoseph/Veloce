iOS-INSPIRED UI PRINCIPLES FOR REACT NATIVE (iOS + ANDROID)
============================================================
A practical summary written for cross-platform React Native work.
This is a paraphrased summary, not Apple's official text. For official
details see Apple's Human Interface Guidelines (HIG).

LICENSING NOTE
- SF Pro font and SF Symbols are licensed for Apple platforms only.
- On Android use: Inter / Roboto (fonts), Ionicons / Lucide / Feather (icons).


PART 1: CORE PRINCIPLES
------------------------------------------------------------
1. CLARITY
   - Text is legible at every size. Icons are simple and recognizable.
   - Every element has an obvious purpose. Remove decoration that does not help.

2. DEFERENCE
   - UI supports the content; it does not compete with it.
   - Use whitespace, light backgrounds, subtle borders. Avoid heavy chrome.

3. DEPTH
   - Use layering (cards, sheets, blur, soft shadows) to show hierarchy.
   - Motion should explain where things come from and go to.

4. CONSISTENCY
   - Same action looks and behaves the same everywhere in the app.
   - Reuse components. Define tokens once (colors, spacing, type, radius).

5. DIRECT MANIPULATION
   - Gestures feel natural: swipe, drag, pull to refresh.
   - Feedback is immediate (press states within ~100ms).


PART 2: LAYOUT AND SPACING
------------------------------------------------------------
- Use a 4pt/8pt grid. Spacing scale: 4, 8, 12, 16, 24, 32, 48.
- Standard screen side margin: 16 (20 for roomier layouts).
- Minimum touch target: 44x44 pt (Android Material says 48x48 dp; use 48
  for both to be safe). Use hitSlop on small icons.
- Respect safe areas (notch, home indicator, status bar).
  Use react-native-safe-area-context (SafeAreaView / useSafeAreaInsets).
- Group related items; separate groups with larger spacing, not lines.
- Align to a consistent left edge.


PART 3: TYPOGRAPHY
------------------------------------------------------------
Suggested scale (size / weight):
  Large Title   34 / bold
  Title         28 / bold
  Headline      17 / semibold
  Body          17 / regular
  Callout       16 / regular
  Subhead       15 / regular
  Footnote      13 / regular
  Caption       12 / regular

Rules:
- Body text never below 12; prefer 15-17 for reading.
- Use weight and size for hierarchy, not many colors.
- Line height roughly 1.2-1.4x font size.
- Support Dynamic Type / font scaling: avoid fixed heights on text
  containers; test with allowFontScaling on.
- Use at most 2 font families.


PART 4: COLOR
------------------------------------------------------------
- Define semantic tokens, not raw colors:
    background, surface, primary, textPrimary, textSecondary,
    separator, success, warning, danger
- Support light AND dark mode (useColorScheme from react-native).
- Text contrast: at least 4.5:1 for body text (WCAG AA).
- One accent color for interactive elements (buttons, links, toggles).
- Do not rely on color alone to convey meaning (add icon or label).
- Typical iOS-like neutrals:
    Light: bg #F2F2F7, surface #FFFFFF, separator #C6C6C8
    Dark:  bg #000000, surface #1C1C1E, separator #38383A


PART 5: NAVIGATION
------------------------------------------------------------
- Tab bar (bottom): 3-5 top-level destinations, always visible.
- Stack navigation: push for drill-down, with a clear back action.
- Modals/sheets: for focused, temporary tasks; always give a way to dismiss.
- Large title headers that collapse on scroll for top-level screens.
- Do not hide primary navigation behind a hamburger menu.

Cross-platform (React Navigation):
- iOS: swipe-from-left-edge to go back (enabled by default in native stack).
- Android: MUST respect the hardware/system back button and gesture.
- Use @react-navigation/native-stack for native feel on both.


PART 6: COMPONENTS
------------------------------------------------------------
BUTTONS
- Primary: filled with accent color. Secondary: tinted or outlined.
- One primary button per screen section.
- Height 44-50, radius 10-14, label 16-17 semibold.
- Show pressed state (opacity ~0.6-0.7 on iOS; ripple on Android).
- Disabled: reduce opacity, block presses, keep label readable.

LISTS
- Rows at least 44 high; 56+ for rows with subtitles/avatars.
- Inset separators (start after the icon/avatar), thin (hairline width).
- Swipe actions for secondary actions (delete, archive).
- Pull-to-refresh via RefreshControl.

FORMS AND INPUTS
- Visible labels or clear placeholders; show errors inline, near the field.
- Correct keyboardType, autoComplete, textContentType, returnKeyType.
- Keep the focused field visible above the keyboard (KeyboardAvoidingView).
- Destructive actions require confirmation (Alert or action sheet).

SWITCHES, SEGMENTED CONTROLS
- Switch: immediate effect, no "save" step needed.
- Segmented control: 2-4 mutually exclusive views of the same content.

SHEETS AND ALERTS
- Bottom sheet for choices/tasks (e.g. @gorhom/bottom-sheet).
- Alerts: short title, 1-2 line message, 1-2 clear actions.
- Destructive action in red; cancel option always present.

EMPTY, LOADING, ERROR STATES
- Never show a blank screen. Provide: skeleton or spinner (loading),
  friendly message + action (empty), retry option (error).


PART 7: MOTION AND FEEDBACK
------------------------------------------------------------
- Durations: 150-300ms for most transitions; ease-in-out or spring.
- Animate meaningful changes only (appear, move, expand).
- Use react-native-reanimated for smooth 60fps animations.
- Haptics for key moments (expo-haptics): success, selection, warning.
  Use sparingly; haptics are subtler on many Android devices.
- Respect "reduce motion" accessibility setting
  (AccessibilityInfo.isReduceMotionEnabled).


PART 8: ACCESSIBILITY
------------------------------------------------------------
- accessibilityLabel on icon-only buttons.
- accessibilityRole (button, header, link, image, etc.).
- accessibilityState for selected/disabled/checked.
- Test with VoiceOver (iOS) and TalkBack (Android).
- Support font scaling and sufficient contrast.
- Logical focus order; do not trap users in modals.


PART 9: WHERE iOS AND ANDROID SHOULD DIFFER
------------------------------------------------------------
Keep shared (same on both):
  spacing scale, type scale, color tokens, card/sheet styles, hierarchy,
  icons, copy and tone.

Make platform-specific:
  - Back behavior: iOS edge swipe; Android system back button/gesture.
  - Press feedback: iOS opacity fade; Android ripple.
  - Alerts/pickers: native look where possible (DateTimePicker etc.).
  - Status bar and navigation bar styling.
  - Shadows: iOS shadow* props; Android elevation.
  - Keyboard behavior: KeyboardAvoidingView behavior "padding" (iOS)
    vs "height" (Android), if needed.
  - Floating Action Button: familiar on Android; on iOS prefer a
    top-right bar button or inline primary button.

// 10.1 Design tokens (theme.ts)
export const spacing = { xs: 4, sm: 8, md: 12, lg: 16, xl: 24, xxl: 32 };
export const radius = { sm: 8, md: 12, lg: 16, pill: 999 };

export const typography = {
  largeTitle: { fontSize: 34, fontWeight: '700' },
  title:      { fontSize: 28, fontWeight: '700' },
  headline:   { fontSize: 17, fontWeight: '600' },
  body:       { fontSize: 17, fontWeight: '400' },
  subhead:    { fontSize: 15, fontWeight: '400' },
  footnote:   { fontSize: 13, fontWeight: '400' },
};

export const lightColors = {
  background: '#F2F2F7', surface: '#FFFFFF', primary: '#007AFF',
  textPrimary: '#000000', textSecondary: '#6C6C70',
  separator: '#C6C6C8', danger: '#FF3B30', success: '#34C759',
};
export const darkColors = {
  background: '#000000', surface: '#1C1C1E', primary: '#0A84FF',
  textPrimary: '#FFFFFF', textSecondary: '#98989D',
  separator: '#38383A', danger: '#FF453A', success: '#30D158',
};

// 10.2 Theme hook
import { useColorScheme } from 'react-native';
export const useTheme = () => {
  const scheme = useColorScheme();
  return scheme === 'dark' ? darkColors : lightColors;
};

// 10.3 Cross-platform pressable button
import { Pressable, Text, Platform } from 'react-native';
export function Button({ label, onPress, disabled }) {
  const c = useTheme();
  return (
    <Pressable
      onPress={onPress}
      disabled={disabled}
      accessibilityRole="button"
      android_ripple={{ color: 'rgba(255,255,255,0.25)' }}
      style={({ pressed }) => ({
        backgroundColor: c.primary,
        height: 50,
        borderRadius: radius.md,
        alignItems: 'center',
        justifyContent: 'center',
        opacity: disabled ? 0.4 : Platform.OS === 'ios' && pressed ? 0.7 : 1,
      })}
    >
      <Text style={[typography.headline, { color: '#FFF' }]}>{label}</Text>
    </Pressable>
  );
}

// 10.4 Card with cross-platform shadow
export const cardShadow = Platform.select({
  ios: {
    shadowColor: '#000', shadowOpacity: 0.08,
    shadowRadius: 12, shadowOffset: { width: 0, height: 4 },
  },
  android: { elevation: 3 },
});

PART 11: PRE-RELEASE CHECKLIST
------------------------------------------------------------
[ ] All touch targets >= 44-48
[ ] Safe areas respected (notch, home indicator, nav bar)
[ ] Light and dark mode both checked
[ ] Text scales without breaking layouts
[ ] Android back button works on every screen
[ ] Loading, empty and error states exist
[ ] Icon-only buttons have accessibility labels
[ ] Contrast >= 4.5:1 for body text
[ ] Keyboard never covers the focused input
[ ] Tested on a small phone, a large phone, and one real Android device


PART 12: PRACTICAL WORKFLOW
------------------------------------------------------------
1. Define tokens first (PART 10.1) before building any screen.
2. Build a small shared component set: Button, Card, ListRow, Input, Header.
3. Build screens only from those components.
4. Add platform-specific tweaks last, with Platform.select.
5. Test on both platforms regularly, not only at the end.
